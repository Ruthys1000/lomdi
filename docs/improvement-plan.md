# תוכנית שיפורים ותיקוני בעיות

מסמך עבודה שמרכז את כל מה שכדאי לתקן ולשפר ב-Lomdi, מסודר לפי גלים שניתן
לבצע ולמזג בנפרד. כל פריט כולל: מה הבעיה, איפה זה בקוד, מה התיקון, ואיך
יודעים שהוא הושלם.

## נקודת הפתיחה

בבדיקה על `main` (commit `d4a5da5`) כל שערי האיכות עוברים:

| בדיקה | תוצאה |
| --- | --- |
| `npm run lint` | עובר |
| `npm run typecheck` | עובר |
| `npm test` | עובר (475 טסטים) |
| `npm run build` | עובר |

**המשמעות:** אין כאן תיקון שבירות דחוף. התוכנית היא הקשחה, ליטוש UX, וסגירת
פערי תחזוקה — ולכן אפשר לבצע אותה בגלים קטנים בלי לייצר סיכון רגרסיה גדול.

## איך עובדים עם התוכנית

- כל גל הוא ענף משלו שמתמזג ל-`main` בסיומו, לפי המקובל בריפו (ראה README,
  "איך שלב מתנהל").
- שערי הקבלה הגלובליים לכל ענף: `npm run lint && npm run typecheck && npm test
  && npm run build` עוברים, ובדיקה בדפדפן אמיתי לפריטים שנוגעים ל-UI.
- פריט שמשנה התנהגות גלויה למשתמש מקבל טסט שמכסה אותה, ולא רק תיקון ידני.

### 1.3 אין מסלול "המשך מאיפה שהפסקת", והרכיב שנבנה לכך הוא קוד מת ✅

- **הבעיה:** `FeaturedProject` מיוצא אך אינו מיובא בשום מקום. בפועל משתמש

  משם: כפתור בפס העליון → מגירה → בחירה מהרשימה.
- **הקוד:** `src/editor/Welcome/RecentProjects.tsx:21`;
  `src/editor/Welcome/WelcomeScreen.tsx:39-41,81-94`.
- **התיקון:** להציג את הלומדה האחרונה כקלף המשך בולט בנחיתה (שימוש ב-
  `FeaturedProject`), עם המגירה כמסלול משני. אם מחליטים שהנחיתה נשארת
  AI-first במכוון — למחוק את הרכיב ואת ההערות שמבטיחות "המשך מהמקום שבו
  הפסקת" (`src/persistence/session.ts:41`), כדי שהקוד לא יתאר מוצר אחר.
- **סיום:** החלטה מתועדת + טסט שמכסה את ההתנהגות שנבחרה. שימו לב ש-
  `WelcomeScreen.test.tsx:78-92` מקבע כיום את ההתנהגות ההפוכה, ויידרש עדכון.
- **ההכרעה:** הנחיתה נשארת **AI-first**, עם בנייה מדף ריק כאפשרות משנית,
  **בלי** מסלול "המשך מהמקום שבו הפסקת" — היצירה היא הפעולה שהדף מוכר, וכרטיס
  המשך היה מתחרה בה על אותו מקום. לפיכך `FeaturedProject` נמחק, ה-hook מחזיר
  רשימה אחת ממוינת במקום פיצול `featured`/`rest`, וההערות שהבטיחו המשך עבודה
  מפנות עכשיו למגירת "הלומדות שלי" — שנשארת הדרך היחידה לעבודה שמורה. נוסף
  טסט שמקבע את ההכרעה, כדי שחזרה לכרטיס המשך תהיה החלטה מפורשת ולא סחף.

## גל 2 — UX ליבה בעורך

הגל עם ההשפעה הגדולה ביותר על תחושת המוצר. כאן נדרשות החלטות עיצוב, לא רק קוד.

### 2.1 פס עליון עמוס, בלי היררכיה ובלי overflow

- **הבעיה:** שורה אחת מכילה לוגו, פותחי מגירות, שם הלומדה, מחוון שמירה,
  undo/redo, בורר תצוגה ושישה כפתורי אייקון — כולם באותו משקל חזותי. בורר
  התצוגה נעלם מתחת ל-`lg` בלי חלופה, ואין תפריט "עוד".
- **הקוד:** `src/editor/Shell/TopBar.tsx:109-223` (בורר תצוגה 180-194,
  אשכול הפעולות 198-223).
- **התיקון:** לקבץ לאזורים בעלי משמעות (עריכה / תצוגה / קובץ וייצוא), לתת
  לייצוא ולתצוגה מקדימה בלטות גבוהה יותר, ולהוסיף תפריט overflow מתחת ל-`lg`
  שמכיל את מה שכיום נעלם.
- **סיום:** כל פעולה נגישה בכל רוחב מסך נתמך; טסט שמאמת שפעולות ה-overflow
  קיימות ברוחב צר.

### 2.2 שם כפתור ההורדה מבלבל בין שמירה לגיבוי

- **הבעיה:** אייקון `Save` מוריד קובץ `.course.zip`, בזמן ש-`Ctrl+S` והשמירה
  האוטומטית שומרים בדפדפן. שני מודלים שונים לחלוטין חולקים את אותה מטאפורה,
  ומשתמש עלול לחשוב שהוא מגובה כשהוא רק שמור מקומית — בעיה אמיתית כי
  IndexedDB הוא לפי origin (README 239-242).
- **הקוד:** `src/editor/Shell/TopBar.tsx:201-206`;
  `src/editor/Shell/SaveIndicator.tsx`.
- **התיקון:** למתג מחדש ל"גיבוי לקובץ" עם אייקון ארכיון, ולהשאיר את שפת
  "שמירה" לאוטוסייב בלבד.
- **סיום:** אין שני פקדים שנקראים "שמירה" עם משמעות שונה.

### 2.3 אין אינדיקציה איזה פרק נערך

- **הבעיה:** הקנבס מציג פרק אחד לפי `selectedChapterId`, אבל שום דבר בקנבס
  לא אומר איזה. בלומדה מרובת פרקים קל לערוך את הפרק הלא נכון. ההסבר קיים —
  אבל רק באינספקטור כשאין בלוק נבחר.
- **הקוד:** `src/editor/Canvas/EditorCanvas.tsx:49,68-72,190`;
  `src/editor/Inspector/CoursePanel.tsx:81-83`.
- **התיקון:** כותרת דביקה מעל הקנבס — "פרק N: {שם}" — עם מעבר לפרק
  הקודם/הבא, מסונכרנת עם המבנה.
- **סיום:** טסט שמאמת שהכותרת משתקפת בבחירת פרק אחר.

### 2.4 פעולות בלוק מבוססות hover

- **הבעיה:** סרגל הבלוק, תגית סוג הבלוק, נקודות ההוספה ופעולות הפרק במבנה
  מתגלים ב-hover. במסך מגע אין hover, ולמשתמש חדש אין רמז שהפעולות קיימות.
- **הקוד:** `src/editor/Canvas/BlockToolbar.tsx:42`;

- **התיקון:** להשאיר את ליטוש ה-hover, אבל להציג אפשרות מינימלית תמיד כאשר

- **סיום:** בדיקה במגע/אמולציית מגע: אפשר לשכפל, להזיז ולמחוק בלוק בלי hover.

### 2.5 בנייד שני הפאנלים סגורים כברירת מחדל

- **הבעיה:** מתחת ל-`lg` המבנה והאינספקטור סגורים, וגם נעילה הדדית (פתיחת
  אחד סוגר את השני). הסשן הראשון בנייד מציג קנבס בלבד, בלי רמז איפה מוסיפים
  פרק או משנים הגדרות.
- **הקוד:** `src/state/editorStore.ts:68-69,108-109`.
- **התיקון:** לפתוח את האינספקטור פעם אחת אוטומטית בבחירת בלוק ראשונה בנייד,
  או להוסיף סרגל תחתון קבוע עם "מבנה" / "הגדרות".
- **סיום:** בדיקה בנייד: אפשר להגיע לשני הפאנלים בלי ידע מוקדם.

### 2.6 אין התמצאות ראשונה בעורך

- **הבעיה:** מי שבוחר "דף ריק" נוחת בעורך תלת-פאנלי בלי כל הכוונה. הזרימות

- **סיום:** אפשר לסגור, ולא חוזרת אחרי סגירה.

## גל 3 — זרימת ה-AI

### 3.1 אין ביטול ואין התקדמות אמיתית ביצירה

- **הבעיה:** היצירה יכולה לרוץ עד כדקה ויותר, והמשתמש מקבל ספינר ומונה
  שניות בלבד: אין דרך לבטל, ואין אינדיקציה שהשרת עדיין עובד. הצד השני כבר
  בנוי לזה — השרת מזרים `progress` כל 10 שניות ומבטל את היצירה כשהלקוח
  מתנתק, והלקוח כבר תומך ב-`signal` וב-`onProgress`. רק הטופס לא משתמש בהם.
- **הקוד:** `src/editor/Welcome/GenerateForm.tsx:37-43,53`;
  `src/ai/generateCourse.ts:14-16,39,59`; `api/generate.ts:95-106`.
- **התיקון:** לחבר `AbortController` לכפתור ביטול ולניקוי ב-unmount, ולהציג
  שלבים על בסיס `onProgress` (למשל "מנתח תוכן…" → "בונה בלוקים…").
- **סיום:** ביטול עוצר את הבקשה בפועל; יציאה מהטופס אינה משאירה בקשה פתוחה.

### 3.2 אילוצי הפורמט אינם נאכפים על התוצר של ה-AI

- **הבעיה:** הפרומפט מבקש מבנה לפי פורמט, והעורך מסתיר בלוקים שאינם מותרים —
  אבל שכבת הריפוי אינה גוזמת. לומדה שנוצרה יכולה לשאת בלוקים שאינם ברשימת
  הפורמט או יותר פרקים ממה שהפורמט מתיר, והם נשארים במסמך (רק מוסתרים
  מספריית הבלוקים).
- **הקוד:** `src/ai/coerceCourse.ts` (הזרקת `format`);
  `src/formats/index.ts:54,167-168`; `src/editor/Outline/OutlinePanel.tsx:95`.
- **התיקון:** שלב `enforceFormatConstraints(course, format)` אחרי הריפוי:
  איחוד/פיצול פרקים לפי `allowChapters`, וגזימה של בלוקים שאינם ב-
  `allowedBlockTypes` עם אזהרה למשתמש.
- **סיום:** טסט לכל פורמט: קלט מזוהם → פלט שמכיל רק מה שהפורמט מתיר.

### 3.3 הגדרות הפורמט מסונכרנות ידנית בין לקוח לשרת

- **הבעיה:** רשימות הבלוקים המותרים קיימות פעמיים, והסינכרון מתועד כידני.
  אין שום דבר שמונע סחף שקט בין העורך לפרומפט.
- **הקוד:** `src/formats/index.ts:79-142`; `api/generate.ts:946,975-1076`.
- **התיקון:** טסט סינכרון שמשווה מזהי פורמטים ו-`allowedBlocks` מול
  `allowedBlockTypes`. הסיבה לכפילות אמיתית (ה-bundler של Vercel לא פותר
  `@/`, ראה `api/generate.ts:11-13`), ולכן הפתרון הוא נעילה בטסט ולא ייבוא.
- **סיום:** שינוי חד-צדדי מפיל טסט עם הודעה שמסבירה מה להוסיף ואיפה.

### 3.4 פיתוח מקומי של ה-AI מבלבל

- **הבעיה:** `npm run dev` הוא ההוראה הראשית ב-README, אבל `/api/generate`
  לא קיים תחת Vite ללא proxy — היצירה תיכשל מקומית ותיראה כמו באג במוצר.
  ההסבר על `vercel dev` מופיע רק בהמשך README וב-`.env.example`.
- **הקוד:** `vite.config.ts` (אין `server.proxy`);
  `src/ai/generateCourse.ts:11`.
- **התיקון:** להבהיר בהוראות ההתקנה מה נדרש ליצירה, ולהוסיף הודעת כשל
  ממוקדת כשהנקודה אינה זמינה בפיתוח.
- **סיום:** מפתח חדש מבין מההודעה מה חסר, בלי לקרוא את כל README.

### 4.1 שמירות אוטומטיות יכולות לרוץ במקביל

- **הבעיה:** ל-`saveNow` אין מנעול על בקשה בתהליך. הקלדה מהירה + flush ב-
  `visibilitychange` + שמירה ידנית יכולים להיכתב במקביל, והמנצח אינו בהכרח
  התמונה העדכנית.
- **הקוד:** `src/persistence/autosave.ts:22-45,68-71`.
- **התיקון:** תור/מנעול עם סמנטיקת "האחרון מנצח": בקשה שמגיעה בזמן כתיבה
  ממתינה לסיום ואז כותבת פעם אחת בלבד.
- **סיום:** טסט שמריץ שתי שמירות במקביל ומאמת סדר כתיבה ותוצאה סופית.

### 4.2 לומדה שמורה פגומה נטענת כפי שהיא

- **הבעיה:** כשאימות נכשל, נכתבת אזהרה לקונסול ומוצג טוסט — והלומדה נטענת
  בכל זאת. זו החלטה מכוונת ומתועדת (עדיף לומדה עם בעיה על משתמש שנחסם), אבל
  היא מכניסה למערכת בדיוק את המצבים שהאימות אמור לתפוס: מזהים כפולים
  ששוברים בחירה, גרירה ומפתחות React.
- **הקוד:** `src/persistence/session.ts:89-116`.
- **התיקון:** להשאיר את הגישה הסלחנית, אבל להוסיף מעבר תיקון best-effort
  לפני הטעינה — כפל מזהים מקבל מזהה חדש, בלוק לא חוקי נזרק — כך שהטעינה
  נשארת אפשרית בלי לשמר מסמך שבור. הטוסט צריך להיות `warning` (ראה 1.2).
- **סיום:** טסט: מסמך עם מזהה כפול נטען עם מזהים ייחודיים.

### 4.3 `exportPath` אינו מוגבל בייבוא

- **הבעיה:** הסכמה מאמתת רק שהמחרוזת אינה ריקה, והייבוא משתמש בה כמפתח
  לקריאה מתוך ה-ZIP. קובץ פרויקט שנבנה בזדון יכול להכיל נתיבים חורגים.
- **הקוד:** `src/model/schema.ts:159`; `src/persistence/projectFile.ts:52,105`.
- **התיקון:** לאמת תבנית קשיחה של `assets/{images|videos|files}/<שם בטוח>`
  ולדחות `..` או נתיב מוחלט.
- **סיום:** טסט עם `exportPath` חורג שנדחה בהודעה ברורה.

### 4.4 אין מצב טעינה בלומדה המיוצאת

- **הבעיה:** בזמן `loadCourseData` אין שום דבר על המסך — במסמך גדול או במכשיר
  איטי זו הבהקה לבנה שנראית כמו תקלה.
- **הקוד:** `src/runtime/main.tsx:36,47`.
- **התיקון:** שלד/הודעת "טוען לומדה…" ב-`#lc-root` עד לרינדור.
- **סיום:** בדיקה מ-`file://` על מסמך גדול.

## גל 5 — נגישות ו-RTL

### 5.1 מודאלים לא עקביים

- **הבעיה:** ספריית הבלוקים והייצוא בנויים על `<dialog>` המובנה (ולכן focus
  trap, Escape ו-inert מגיעים חינם), אבל התצוגה המקדימה היא `div` עם
  `role="dialog"` — כלומר התנהגות מקלדת וקורא מסך שונה במסך מרכזי.
- **הקוד:** `src/editor/Preview/PreviewOverlay.tsx:49`;
  `src/editor/BlockLibrary/BlockLibraryModal.tsx:74`;
  `src/editor/Export/ExportDialog.tsx:93`.
- **התיקון:** להעביר את התצוגה המקדימה לאותה תבנית `<dialog>`.
- **סיום:** Escape סוגר, המיקוד נכנס פנימה ואינו בורח מאחור.

### 5.2 לשוניות ספריית הבלוקים הן תבנית ARIA חלקית

- **הבעיה:** יש `role="tab"` ו-`aria-selected`, אבל אין `tabpanel`,
  `aria-controls`, או ניווט חיצים — קורא מסך מקבל רשימת לשוניות בלי פאנל.
- **הקוד:** `src/editor/BlockLibrary/BlockLibraryModal.tsx:116-117`.
- **התיקון:** להשלים את התבנית או לעבור ל-radiogroup, שמתאים יותר לסינון.
- **סיום:** מעבר מקלדת מלא בין הקטגוריות.

### 5.3 בורר מקטעים בלי ניווט חיצים ✅

- **הבעיה:** `role="radio"` בלי roving tabindex ובלי מקשי חצים; בפועל צריך
  Tab על כל אפשרות. זה גם סותר את התיעוד של הרכיב (ראה 1.6).
- **הקוד:** `src/editor/controls/Field.tsx:113-134`.
- **התיקון:** ניווט חיצים לפי תבנית radiogroup, או רדיו נייטיב מעוצב.
- **סיום:** טסט מקלדת: חץ מזיז בחירה, Tab יוצא מהקבוצה.
- **בוצע בגל 1**, כי בלעדיו התיעוד ב-1.6 היה נשאר שקר. החצים מודעי-כיווניות
  (ב-RTL חץ שמאלה מתקדם), הפוקוס נודד עם הבחירה, ולערך לא-מוכר נשמרת נקודת
  כניסה אחת ל-Tab. שימו לב ש-`getComputedStyle().direction` אינו יורד בירושה
  ב-jsdom, ולכן הזיהוי נקרא מהמאפיין `dir` בעץ — גרסה שנשענה על החישוב עברה
  את הטסט מהסיבה הלא נכונה.

### 5.4 התקדמות קריאה מוסתרת מקוראי מסך

- **הבעיה:** פס ההתקדמות במצב גלילה מסומן `aria-hidden`, ולכן לומד שמשתמש
  בקורא מסך לא מקבל שום חיווי התקדמות — בזמן שמצב הפרקים כן חושף חיווי.
- **הקוד:** `src/renderer/ScrollNavigation.tsx:61`;
  `src/renderer/ChapterNavigation.tsx`.
- **התיקון:** `role="progressbar"` עם `aria-valuenow` לפי מצב הגלילה.
- **סיום:** קורא מסך מדווח התקדמות בשני מצבי הניווט.

### 5.5 פרטי RTL ורספונסיביות

- **הבעיה:** כמה נקודות ליטוש שנשארו: חץ חזרה פיזי שמאלה בממשק RTL
  (`src/editor/Welcome/FormatGallery.tsx:153`), טבלת סטטיסטיקות בייצוא
  ב-`grid-cols-4` בלי breakpoint (`src/editor/Export/ExportDialog.tsx:136`),
  וסדר כפתורים בדיאלוג אישור שמציב את הפעולה ההרסנית ראשונה
  (`src/editor/ui/ConfirmDialog.tsx:55-72`).
- **התיקון:** חץ מודע-כיוון, `grid-cols-2` במסכים צרים, וביטול לפני אישור
  בפעולות הרסניות.
- **סיום:** בדיקה בנייד ובדסקטופ; אין גלישה או צפיפות בטקסט.

## גל 6 — תשתית, אבטחה ואיכות

### 6.1 `/api/generate` פתוח לכל דורש

- **הבעיה:** הפונקציה מאמתת שיטה, קיום טקסט ואורך — ואין בה אימות זהות או
  הגבלת קצב. כל מי שמגיע לכתובת יכול להפעיל יצירות Opus (`max_tokens:
  32_000`, עד שני ניסיונות, `maxDuration: 800`) על חשבון ה-API. זהו הפריט
  היחיד ברשימה שהוא סיכון עלות ישיר, ולכן העדיפות הגבוהה ביותר בגל.
- **הקוד:** `api/generate.ts:22-49`.
- **התיקון:** אימות (טוקן/סשן או הגנת Vercel), הגבלת קצב לפי IP/משתמש,
  ותקרת בקשות. יש לוודא שהמגבלות חלות לפני `res.flushHeaders()`, כי מרגע
  שהכותרות נשלחו אין דרך להחזיר קוד שגיאה תקני.
- **סיום:** בקשה מעל התקרה מקבלת 429 בלי לפנות ל-Anthropic.

### 6.2 תלויות פגיעות

- **הבעיה:** `npm audit` מדווח 12 פגיעויות, מרביתן דרך `@vercel/node`
  (תלות פיתוח). הסיכון בפועל נמוך כי זו אינה תלות ריצה של הלומדה, אבל היא
  כן נכנסת לסביבת הפיתוח וה-CI.
- **הקוד:** `package.json` (`@vercel/node` תחת devDependencies).
- **התיקון:** לבדוק שדרוג, או `overrides` לתלויות המשניות, ולוודא ש-`api/`
  עדיין מתקמפל ורץ.
- **סיום:** `npm audit` נקי מ-high, או פגיעות שנותרה מתועדת עם נימוק.

### 6.3 `api/generate.ts` הוא מונולית של ~1,130 שורות

- **הבעיה:** בקובץ אחד יושבים ה-handler, שכבת ריפוי ה-JSON, כל הפרומפטים,
  הדוגמאות ומודולי הפורמטים. זה מקור הסחף שתואר ב-3.3, וגם מקשה על טסטים
  (`src/ai/repairJson.test.ts` מייבא ישירות מתוך `api/`).
- **הקוד:** `api/generate.ts:160-341` (ריפוי), `343-1128` (פרומפטים).
- **התיקון:** לחלץ מודולים טהורים לתיקייה משותפת שגם ה-bundler של Vercel וגם
  Vitest יכולים לייבא. אילוץ הבסיס אמיתי ומתועד (`api/generate.ts:11-13`),
  ולכן החילוץ חייב להישאר בלי alias ובלי גרף האפליקציה.
- **סיום:** הפונקציה עולה בפרודקשן אחרי הפיצול; הטסטים מייבאים מהמודול המשותף.

### 6.4 כיסוי טסטים חסר בבלוקים ובחוזה הריצה

- **הבעיה:** שני פערים ממשיים: טסט חבילת הריצה מאמת 9 סוגי בלוקים מתוך 15,
  ומתוך 15 תיקיות בלוקים רק 8 מכוסות בטסטים — כלומר רגרסיה ב-Renderer של
  בלוק חדש לא בהכרח תיתפס.
- **הקוד:** `src/runtime/runtimeBundle.test.ts:126-140`;
  `src/blocks/registry.runtime.ts:33-49`.
- **התיקון:** לגזור את רשימת הסוגים מהרגיסטרי במקום לכתוב אותה ידנית, ולהוסיף
  טסט smoke ל-Renderer של כל בלוק (התבנית קיימת ב-`accordion` וב-`quiz`).
- **סיום:** בלוק חדש שנרשם ולא נכנס לחבילה מפיל טסט.
- **חצי בוצע בגל 1:** רשימת הסוגים בטסט חבילת הריצה נגזרת מהרגיסטרי. טסטי
  ה-smoke לכל Renderer עוד חסרים.

### 6.5 חבילת העורך חורגת מ-1MB

- **הבעיה:** ה-build מזהיר על נתח מעל 1MB (‎~308KB gzip), בעיקר בגלל תלויות
  עורך בלבד (TipTap, dnd-kit, אייקונים). זה נטל טעינה על היוצר, ולא על הלומד.
- **התיקון:** פיצול דינמי לפי פאנל/מודאל (ספריית בלוקים, ייצוא, עורכי טקסט).
- **סיום:** אין אזהרת chunk ב-build, בלי רגרסיה בזרימות.

### 6.6 שערי איכות בפיתוח

- **הבעיה:** אין Prettier/EditorConfig, אין hook לפני commit, ואין דיווח
  כיסוי ב-CI — כך שהפערים בסעיף 6.4 אינם נראים לעין.
- **הקוד:** `.github/workflows/ci.yml`; `vitest.config.ts`.
- **התיקון:** Prettier + כיסוי ב-CI (בהתחלה כדיווח, לא כשער חוסם).
- **סיום:** CI מדווח כיסוי; פורמט אחיד נאכף אוטומטית.
