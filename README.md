# לומדי — מחולל לומדות HTML מבוסס בלוקים

כלי ויזואלי לבניית לומדות בעברית: המשתמש בונה לומדה מפרקים ובלוקים, עורך אותה
ישירות על הקנבס, שומר את הפרויקט וממנו מייצא **לומדת HTML עצמאית** — כזו שרצה
מפתיחת `index.html` בלי שרת, בלי CDN ובלי תלות במחולל, וניתנת להעלאה ל-Moodle
כתיקיית תוכן או כ-ZIP.

> סטטוס: אב-טיפוס (POC) בפיתוח. שלבים 1–7 הושלמו — **כל תשעת סוגי הבלוקים
> עובדים**, העבודה נשמרת אוטומטית בדפדפן, אפשר לייצא ולייבא קובץ פרויקט
> `.course.zip` עם הנכסים, **ו-ZIP של לומדה עצמאית שרצה מ-`file://`**.

## התקנה והרצה

דרישות: Node.js 20 ומעלה.

```bash
npm install
npm run dev
```

הכתובת תודפס לטרמינל (ברירת מחדל: <http://localhost:5173>).

## הארכיטקטורה בקצרה

מקוד מקור אחד נבנות **שתי** חבילות:

| חבילה | Entry | תוצר | מה בפנים |
| --- | --- | --- | --- |
| **עורך** | `src/main.tsx` | `dist/` | האולפן: סרגלים, פאנלים, גרירה, TipTap, שמירה, ייצוא |
| **runtime של הלומדה** | `src/runtime/main.tsx` | `public/runtime/app.js` + `styles.css` | React + `CourseRenderer` + ה-Renderers של הבלוקים בלבד. **IIFE ולא ESM** — מודול אינו רץ מ-`file://` |

שתיהן מייבאות את אותם רכיבי `Renderer`. לכן התצוגה המקדימה בעורך והלומדה
המיוצאת אינן שתי מימושים שצריך לסנכרן — הן אותה יחידת קוד. בזמן ייצוא, העורך
אורז את `public/runtime/` לתוך ה-ZIP.

מכאן נגזרות שבע מוסכמות שהפרתן שוברת את התוצר:

1. **קוד עורך לא נכנס לאזור ה-Renderer.** `src/renderer/**`, `src/runtime/**`
   ו-`src/blocks/*/Renderer.tsx` אינם מייבאים מ-`editor/`, מה-stores, מ-TipTap
   או מ-dnd-kit. הכלל נאכף ב-`eslint.config.js` — הפרה מפילה את ה-lint.
2. **שלושה רגיסטרים, לא אחד.** רגיסטרי מאוחד היה גורר את כל העורך — ואת zod —
   לחבילת הלומדה בכל ייבוא:

   | קובץ | מה בפנים | מי צורך |
   | --- | --- | --- |
   | `blocks/labels.ts` | שמות הבלוקים בעברית. אפס תלויות | כולם |
   | `blocks/registry.shared.ts` | סכמות zod, תוכן ברירת מחדל, נכסים בשימוש | המודל, הייצוא, העורך |
   | `blocks/registry.runtime.ts` | רכיבי Renderer בלבד | הלומדה המיוצאת |
   | `blocks/registry.editor.tsx` | Editor / Settings / אייקונים | העורך |
3. **טקסט עשיר נשמר כ-JSON של ProseMirror, לא כ-HTML.** `renderer/RichTextView`
   ממיר את העץ ל-React דרך רשימה לבנה מפורשת של nodes ו-marks. אין בפרויקט
   `dangerouslySetInnerHTML` ואין sanitizer בזמן ריצה — אין נתיב בקוד שממיר
   מחרוזת ל-HTML, ולכן גם קובץ פרויקט שנערך ידנית לא יכול להזריק סקריפט.
   כל פורמט חדש בסרגל העריכה מחייב שורה גם ברנדרר; זה מכוון.
4. **בלוקים שומרים `assetId`, לעולם לא כתובת.** ההמרה לכתובת נעשית דרך
   `resolveAssetUrl` ב-`RenderContext`: `blob:` בעורך, נתיב יחסי בייצוא. כך
   מובטח מבנית שנתיבי `blob:` לא יכולים לדלוף לתוצר.

5. **הגבול נבדק על התוצר הבנוי, לא רק על הקוד.** כלל ה-ESLint תופס ייבוא
   ישיר בלבד; דליפה שנכנסת דרך שרשרת ייבוא — למשל ייבוא פונקציית עזר כערך
   מקובץ שמייבא zod — עוברת אותו. `runtime/runtimeBundle.test.ts` סורק את
   `public/runtime/app.js` עצמו ומוודא שאין בו zod, TipTap, dnd-kit, zustand,
   JSZip או IndexedDB, ושאין בו הפניה למארח חיצוני מלבד יוטיוב ו-Vimeo.
6. **נכסים אינם חלק מ-`Course`, ולכן אינם ב-Undo.** `ProjectFile` מפריד
   `course` מ-`assets` מהיום הראשון, וההפרדה נשמרת גם ב-state: המסמך ב-
   `courseStore` (עם היסטוריה), הנכסים ב-`assetStore` (בלי). Blob אינו ניתן
   לביטול בצורה משמעותית — undo היה מחזיר רשומה שמצביעה לקובץ שכבר נמחק —
   ובלוק ששוכפל חייב להצביע לאותו נכס ולא לעותק שלו.
7. **`course.css` לא נשען על ברירות מחדל של הסביבה.** בעורך הוא חי בתוך מסמך
   שה-preflight של Tailwind כבר אתחל, ובתוצר הוא לבד. כל מאפיין שנסמך על
   ברירת מחדל של הדפדפן ייראה שונה בשתי הסביבות — זה כבר קרה עם תבליטי
   רשימה. `course.css.test.ts` נועל את המאפיינים הרגישים.

`public/runtime/` ו-`public/fonts/` הם תוצרי build ולכן אינם נשמרים בגיט.
`npm run dev` ו-`npm run build` בונים אותם קודם, כדי שהייצוא לא ישלח רנדרר
מיושן או ZIP בלי גופן.

## גופנים

הגופנים העבריים **נארזים לתוך התוצר** ואינם נטענים מ-CDN: לומדה שרצה
מ-`file://` בלי אינטרנט אינה יכולה למשוך גופן מהרשת, וגופן שאינו מותקן אצל
הלומד פשוט אינו קיים. בלי ההטמעה, בורר הגופנים ב-Theme Builder הוא הבטחה
ריקה, והעורך והתוצר נראים שונה זה מזה — בדיוק מה שהארכיטקטורה נבנתה למנוע.

`scripts/build-fonts.mjs` מחלץ מ-`@fontsource-variable` את שלוש המשפחות
(Heebo, Assistant, Rubik) אל `public/fonts/`. שלוש החלטות בתוכו:

- **גופן משתנה** — קובץ אחד לכל תת-קבוצה מכסה משקלים 100–900, ולכן
  כותרות ב-600, 700 ו-800 אינן דורשות שלושה קבצים.
- **עברית ולטינית בלבד.** `latin-ext`, `math` ו-`symbols` מוסיפים כ-56KB
  למשפחה עבור תווים שלומדה בעברית כמעט לעולם אינה מציגה.
- **ה-CSS מועתק מהחבילה ולא נכתב ביד.** ה-`unicode-range` של כל תת-קבוצה
  הוא מקור אמת ארוך ורגיש; טעות בו נראית כמו "העברית עובדת אבל הספרות
  נשברות".

העורך טוען את שלוש המשפחות ב-`index.html` (הדפדפן מוריד קובץ גופן רק
כשמשפחה מרונדרת בפועל), והייצוא אורז **רק את המשפחה שהערכה בחרה** —
כ-42KB. "גופן המערכת" אינו אורז דבר.

הגופנים ברישיון SIL Open Font License 1.1, ולכן `fonts/OFL.txt` נארז לצדם
בכל ZIP: הרישיון מחייב שהוא ילווה את הקבצים בכל הפצה.

## שמירה, קובץ פרויקט ונכסים

**שמירה אוטומטית.** כל שינוי במסמך או ברשימת הנכסים נשמר ל-IndexedDB אחרי
1.2 שניות של שקט, ומעבר ללשונית אחרת מאלץ שמירה מיידית (`beforeunload` לא
מספיק — כתיבה ל-IndexedDB אסינכרונית). השמירה מאזינה ל-`courseStore` ול-
`assetStore` בלבד: בחירת בלוק או פתיחת פאנל אינן שינוי במסמך, ולכן אינן
כותבות. `Ctrl/Cmd+S` שומר מיד; הורדת קובץ פרויקט היא פעולה נפרדת בסרגל.

**שלוש חנויות ב-IndexedDB** (בסיס נתונים `learnit` — השם ההיסטורי נשמר בכוונה, כדי ששינוי שם המוצר לא ייתם לומדות שכבר שמורות בדפדפן):

| חנות | מפתח | מה בפנים |
| --- | --- | --- |
| `projects` | `course.id` | ה-JSON של הפרויקט. נכתב בכל שמירה |
| `assets` | `asset.id` | ה-Blob עצמו + `AssetMeta`, עם אינדקס `projectId` |
| `meta` | `lastProjectId` | הפרויקט האחרון שנפתח |

הבלובים נכתבים פעם אחת בהעלאה ואינם נוגעים בשמירה האוטומטית — אחרת כל
הקלדה הייתה מעתיקה מחדש עשרות מגה-בייט של תמונות.

**קובץ הפרויקט — `.course.zip`:**

```
course.json                          ← ProjectFile: version, generator, savedAt, course, assets
assets/images/asset-a1b2c3d4e5.jpg   ← בדיוק לפי AssetMeta.exportPath
assets/videos/asset-f6g7h8i9j0.mp4
```

הנתיבים בארכיון הם אותם `exportPath` שנמצאים בתוצר המיוצא, ולא סכמה
מקבילה. ייבוא מריץ את אותו `validateProjectFile` של המודל, כולל המיגרציות:
קובץ פגום נדחה בהודעה בעברית, ונכס שקובצו חסר בארכיון יורד עם אזהרה במקום
להפיל את הטעינה.

**שמות קבצים.** הנכס נשמר בשם שנגזר ממזההו (`asset-a1b2c3d4e5.jpg`) ולא משם
הקובץ שהועלה: שם עברי אינו עובר את `assetMetaSchema` ולא שורד ZIP במערכות
קבצים שונות. השם המקורי נשמר ב-`originalName` לתצוגה. גם שם קובץ ההורדה
הוא ASCII — Chromium משמיט שם שאינו ASCII ומוריד במקומו קובץ בשם `download`
בלי סיומת, שהמשתמש כבר לא יכול לפתוח בחזרה.

ספריית הנכסים מקבלת תמונות (JPG, PNG, WebP, GIF, AVIF, SVG) וסרטונים (MP4,
WebM). SVG מותר כי הוא מוצג אך ורק דרך `<img src>` — הקשר שמנטרל סקריפטים
בתוך הקובץ, ולכן מוסכמה 3 נשמרת.

## ייצוא הלומדה — ZIP עצמאי

הכפתור האחרון בסרגל פותח חלון שמראה מה ייארז ומה כדאי לדעת לפני ההורדה
(בלוק שמפנה לנכס חסר, סרטון שדורש אינטרנט, נכסים שאינם בשימוש). אף אזהרה
אינה חוסמת ייצוא — לומדה חלקית שווה יותר מכפתור מושבת בלי הסבר.

```
lomdi-safety-2026-07-25.zip
└─ lomdi-safety-2026-07-25/
   ├─ index.html                        ← JSON מוטמע + משתני הערכה inline
   ├─ content.json                      ← אותו payload, לשימוש בהגשה משרת
   ├─ runtime/app.js                    ← מועתק מ-public/runtime/
   ├─ runtime/styles.css
   ├─ fonts/heebo.css + woff2 + OFL.txt ← רק המשפחה שהערכה בחרה
   ├─ assets/images/asset-a1b2c3d4e5.jpg  ← בדיוק לפי AssetMeta.exportPath
   └─ README.txt                        ← הוראות בעברית, עם BOM ל-Notepad
```

**מה מחזיק את הבטחת ה-`file://`:**

- **סקריפט קלאסי, לא `type="module"`.** מודול נטען כבקשת CORS, ותחת
  `file://` המקור הוא `null` — כלומר מודול פשוט לא ירוץ בדאבל-קליק. לכן
  חבילת הלומדה נבנית כ-IIFE יחיד.
- **הנתונים מוטמעים ולא נטענים ב-`fetch`.** דפדפנים חוסמים `fetch` של
  קובץ מקומי; `content.json` הוא גיבוי לשימוש משרת בלבד.
- **כל הנתיבים יחסיים** — אין `/` מוביל ואין מארח, כדי שהתיקייה תעבוד גם
  בשורש דיסק, גם בתת-תיקייה של Moodle וגם מ-Disk-on-key.
- **תיקיית שורש אחת בארכיון.** פריקה לתוך תיקיית ההורדות לא מפזרת שישה
  פריטים, וב-Moodle התיקייה עולה כיחידה אחת.
- **רק נכסים שבשימוש נארזים** — ומאותה סיבה הם גם היחידים שנרשמים ברשימה
  המוטמעת: נתיב לקובץ שלא נארז הוא תמונה שבורה אצל הלומד.
- **`export/exportedCourse.test.ts` פורק ZIP אמיתי לתיקייה זמנית ופותח
  את `index.html` מ-`file://`.** זו הבדיקה היחידה שרואה את מה שהמשתמש
  רואה; נתיב שגוי נראה תקין בכל בדיקה שמסתכלת רק על המחרוזת.

`src/export/` מחולק לפי אחריות: `payload` (מה נכנס), `indexHtml` (איך
נראה הקובץ), `exportZip` (מבנה הארכיון), `runtimeBundle` (מאיפה מגיעה
החבילה), `checks` (האזהרות) ו-`exportCourse` (התזמור, הצד היחיד שנוגע
ב-stores).

> **הייצוא נשען על `public/runtime/`.** אם הוא חסר — למשל אחרי `vite build`
> בלבד — הייצוא נעצר עם הודעה שמפנה ל-`npm run build`, במקום לייצר ZIP עם
> לומדה שלא עולה.

## פריסה (Vercel)

`vercel.json` מגדיר `buildCommand: npm run build` ו-`outputDirectory: dist`.
שתי ההגדרות אינן קוסמטיות:

- **`npm run build` ולא `vite build`.** `public/runtime/` אינו בגיט, ורק
  ה-build המלא בונה אותו לפני העורך. `vite build` לבדו היה מייצר אתר
  שהייצוא בו שולח חבילת לומדה ריקה — כלומר תקלה שמתגלה רק אחרי הורדת ZIP.
- **אין `rewrites`.** אין ראוטר בפרויקט; הכול חי תחת `index.html` אחד.

העריכה, השמירה והייצוא רצים כולם בדפדפן, והתוכן שנבנה בעורך לא עוזב אותו.
**היוצא מן הכלל הוא יצירת לומדה מ‑AI** (ראה למטה): שלב היצירה שולח את הטקסט
שהוזן לפונקציית שרת ולספק ה‑AI.

## יצירת לומדה מ‑AI

הדבקת תוכן במסך הפתיחה מחוללת לומדה שלמה. מפתח ה‑API של Anthropic חי **רק
בשרת** ולעולם לא מגיע לדפדפן:

- **`api/generate.ts`** — פונקציית serverless של Vercel. מקבלת `POST { text }`,
  בונה את הפרומפט מ‑`buildGenerationContract()` (`src/ai/contract.ts`), קוראת
  ל‑Claude בסטרימינג, ומחזירה JSON גולמי של לומדה. היא חד‑תכליתית בכוונה — רק
  טקסט→לומדה — כדי לא להפוך לממסר פתוח שמריץ כל פרומפט על חשבון המפתח.
- **הלקוח** (`src/ai/generateCourse.ts`) מריץ את הפלט הגולמי דרך
  `importGeneratedCourse` (ריפוי + ליטוש + אימות), פותר כוונות תמונה לאיורי
  מציב‑מקום, ומעביר ל‑`openCourse`. שכבת ה‑AI כולה יושבת בצד העורך ולא נכנסת
  לחבילת ה‑runtime.
- **תמונות** (`api/image.ts`) — Claude מייצר תיאור תמונה (`query`), לא תמונה.
  ה‑endpoint מחפש ב‑**Pexels**, מושך את בייטי התמונה בצד השרת, ומחזיר אותם
  מאותו origin — כך `importAssetFromUrl` מטמיע אותם כ‑Blob ללא CORS, והלומדה
  עובדת אופליין. הבחירה בספק חיה מאחורי ה‑`ImageResolver` (`src/ai/imageResolver.ts`);
  החלפה ל‑AI‑generated בעתיד היא שינוי ב‑endpoint בלבד. בכל כשל (אין מפתח, אין
  תוצאה) נופלים חזרה לאיורי מציב‑מקום.
- **משתני סביבה** — `ANTHROPIC_API_KEY` (יצירה) ו‑`PEXELS_API_KEY` (תמונות)
  נקבעים ב‑Vercel → Project → Settings → Environment Variables (Production +
  Preview), לעולם לא בריפו. לפיתוח מקומי: `.env` (ב‑gitignore, ראה
  `.env.example`) והרצה עם `vercel dev`.
  **חשוב:** משתנה סביבה חדש נכנס לתוקף רק אחרי **redeploy**, וחייב להיות מסומן
  לסביבת **Production**. "הגדרתי `PEXELS_API_KEY` ועדיין אין תמונות" הוא כמעט תמיד
  אחד מהשניים. כשל בטעינת תמונה כבר אינו שקט — הודעת ה‑toast אחרי היצירה מציגה
  את הסיבה (מפתח שגוי, חריגת מכסה, אין תוצאה).

> **IndexedDB הוא לפי origin.** פרויקט שנשמר אוטומטית ב-`localhost` לא יופיע
> בכתובת הפרוסה, ומכיוון שלכל preview deployment יש כתובת משלו — גם לא יעבור
> בין פריוויוז. זה נראה כמו אובדן עבודה והוא לא. לבדיקת שמירה אוטומטית יש
> להשתמש בדומיין הפרודקשן היציב, ובפריוויוז לבדיקות ויזואליות בלבד.

## מבנה התיקיות

```
src/
  model/       מודל התוכן: טיפוסים, סכמות, פעולות טהורות. ללא תלות ב-React
  blocks/      תיקייה לכל סוג בלוק: Renderer / Editor / Settings / הגדרה
  renderer/    מה שהלומד רואה — משותף לתצוגה מקדימה ולתוצר
  runtime/     נקודת הכניסה של הלומדה המיוצאת
  editor/      האולפן: סרגלים, קנבס, פאנלים, ספריות
  state/       zustand: מסמך הלומדה (נשמר) מול מצב העורך (לא נשמר)
  persistence/ IndexedDB, שמירה אוטומטית, קובץ פרויקט, מחזור חיי הפרויקט
  export/      בניית ה-ZIP וה-index.html
```

### איך שלב מתנהל

כל שלב מתפתח בענף משלו ומתמזג ל-`main` בסיומו, אחרי ש-`npm run lint &&
npm run typecheck && npm test && npm run build` עוברים ואחרי בדיקה בדפדפן
אמיתי. `main` הוא ענף הפרודקשן שממנו Vercel פורסת, ולכן הוא אמור להיות
תמיד במצב עובד — שלב באמצע העבודה לא יושב עליו.

## קיצורי מקלדת

| קיצור | פעולה |
| --- | --- |
| `Ctrl/Cmd+Z` | ביטול |
| `Ctrl/Cmd+Shift+Z` | ביצוע מחדש |
| `Ctrl/Cmd+S` | שמירה מיידית לדפדפן (לא הורדת קובץ) |
| `Delete` | מחיקת הבלוק הנבחר, עם אישור |
| `Escape` | ביטול בחירה או סגירת חלון |

בתוך שדה טקסט או עורך טקסט עשיר, `Ctrl+Z` שייך לעריכה ולא לאפליקציה — אחרת
ביטול של תו אחד היה מוחק בלוק שלם.
